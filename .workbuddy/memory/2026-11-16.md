## 删除被占用文件修复(重点)
- 问题:trash 删除 Temp 下被进程占用的文件报 0x80270027 共享冲突。
- 方案:新增 `src-tauri/src/engine/win_lock.rs`(仅 Windows 编译):
  - Restart Manager(RmStartSession/RmRegisterResources/RmGetList)查占用进程;
  - 结束进程后重试 trash 删除;deleter.rs 中命中 in-use 错误码时触发;
  - 安全策略:跳过自身 PID、PID<=4、%SystemRoot% 下的系统进程。
- 新增 windows crate 0.61 依赖(features: RestartManager/Threading/Foundation)。
- windows-rs 0.61 API 细节:RmStartSession 第2参是 Option<u32>、session key 要 PWSTR(可变);RmGetList reboot_reasons 是必传 *mut u32;RM_PROCESS_INFO 字段名是 strAppName;QueryFullProcessImageNameW flags 要 PROCESS_NAME_FORMAT(0)。

## 卸载路径错误修复(重点)
- 现象:点「卸载」弹 Windows 对话框 "cannot find the file \C:\...\unins000.exe\"(路径前多一个反斜杠)。
- 根因:旧实现 `cmd /C start "" <UninstallString>`,Rust `Command::args` 会把内嵌 `"` 转义成 `\"`,cmd.exe 不认反斜杠转义 → 路径被解析成 `\C:\...\`。
- 方案:新增 `src-tauri/src/engine/uninstall.rs::split_command`,自行解析 UninstallString(带引号 / 无引号含空格 / 裸程序名 / 仅目录四种写法),再直接 `Command::new(program).args(...)` 启动:
  - 目录型卸载项 → `explorer <dir>`;
  - .bat/.cmd → `cmd /C` + `raw_arg` 保留原始引号;
  - 程序不存在 → 明确报"卸载程序不存在"。
- 测试:解析逻辑 4 个用例加到 `src-tauri/tests/engine.rs`(共 9 个测试通过)。

## 扫描中删除/界面卡死修复
- 「扫描中删除无效」根因有两层:前端 `performDelete` 要求 `phase==='done'` 直接 return(无提示);后端 `delete_paths` 也硬拒绝 `scanning`。
- 「停止/右键都点不动」:Rust 每秒 `build_partial` 克隆整棵树 + 1 万条 TopN 并序列化,把 WebView 主线程压死。
- 方案:
  - 删除放开:后端移除 scanning 拦截,删除成功的路径在扫描中暂存 `pending_deletes`(state.rs),Done 时 `apply_deleted` 扣减;前端允许 scanning 期删除,并用 `deletedPaths` 过滤快照里"复活"的行。
  - 卡顿:快照自适应间隔 `snap_gap = max(1s, 构建耗时×8)`;快照 top_files 截断到 1500 条(SNAPSHOT_TOP_LIMIT)。

## exe 图标不更新(任务栏/跳转列表仍显示旧 logo)
- 现象:界面已用新 logo,但任务栏预览/跳转列表标题栏仍是旧的双环图标。
- 根因:`tauri icon` 只是重新生成 `src-tauri/icons/*`,exe 图标是编译期由 tauri-build 写进资源段的;build.rs 没声明 `rerun-if-changed`,Cargo 不重跑构建脚本 → exe 里保留旧图标。
- 方案:`src-tauri/build.rs` 显式 `cargo:rerun-if-changed` 各图标文件,再重编译即生效(已用 pefile 提取 exe RT_ICON 校验为新 logo)。
- 排查手法:`python + pefile` 读 PE 的 RT_GROUP_ICON/RT_ICON 导出 256px 图标对比哈希,比看截图可靠。

## 扫描中切换路由的后台清理
- 问题:扫描中切路由只解绑了事件监听,Rust 扫描线程继续空转,回来后重扫还会被「扫描正在进行中」挡住。
- 方案:两个视图 `onBeforeUnmount` 时主动取消(`cancelScan` / `cancelJunk`,删除任务不取消让它跑完);后端 `start_scan`/`scan_junk` 遇到占用标志时不再直接报错,先补一发取消信号并轮询等待(最多 2s)旧线程退出,让「切走再回来立刻重扫」无缝衔接。
- 细节:`scan_junk` 用 swap(true) 占标志,等待旧线程 store(false) 后必须重新 store(true),否则新扫描期间标志是 false 会放进并发扫描。
