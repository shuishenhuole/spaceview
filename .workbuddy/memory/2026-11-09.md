# 2026-11-09

## 删除任务改为后台执行(避免 UI 卡死)

- 根因:`app.rs::perform_delete` 在 UI 线程同步调用 `trash::delete`,Windows 上走 Shell COM `IFileOperation::PerformOperations`,大目录/批量删除会长时间阻塞重绘。
- 方案:新增 `src/engine/deleter.rs`,工作线程逐项删除并通过 mpsc 发送 `Started/Item/Done`;`trash` 按 thread_local 初始化 COM,后台线程可独立调用。用 `catch_unwind` 把 COM panic 转成普通错误,保证通道以 Done/断开收尾。
- UI 侧:`SpaceViewApp.deleting: Option<DeleteJob>`,`logic()` 每帧 `poll_delete_events` 只累计进度(100ms 低频重绘),任务结束时用新增的 `ScanResult::apply_deleted` 一次性批量同步目录树/TopN/扩展名/总量,避免逐项线性查找的 O(n²) 主线程卡顿。
- 配套:状态栏进度条+当前项+“取消剩余”(只跳过未开始项,单次 Shell 调用不可中断);工具栏删除中禁用开始扫描与目标切换;`view_epoch` 保护结果不同步到新一轮扫描;失败项/取消剩余项回到勾选集合,成功项从勾选集合剔除。
- 保持 `trash` 默认 feature(coinit_apartmentthreaded),未改依赖。
- 验证:`cargo check --all-targets` 通过;`cargo test --all-targets` 9 个测试全绿(新增 3 个集成测试:后台事件顺序、取消跳过、批量模型同步)。
- 改动文件:新增 `src/engine/deleter.rs`;修改 `app.rs`、`engine/mod.rs`、`engine/scanner.rs`、`ui/status_bar.rs`、`ui/toolbar.rs`、`tests/scan_smoke.rs`、`CHANGELOG.md`。
